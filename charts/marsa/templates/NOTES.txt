No DNS yet? The web UI is reachable directly by node IP — a catch-all route
serves marsa-web on any host. The API and the api.<domain> route are host-based,
so those need the hostnames below to resolve.

Find the node IP:

  kubectl get nodes -o wide          # use the EXTERNAL-IP (or INTERNAL-IP on a LAN)

  http://<node-ip>/                  # web UI works by raw IP

For the full domain experience (and the API), point a DNS A record at that IP,
or for a quick local test add to /etc/hosts:

  <node-ip>  {{ .Values.tls.domain }}  api.{{ .Values.tls.domain }}

{{- if .Values.tls.enabled }}

TLS is enabled via Let's Encrypt (Traefik ACME resolver). The cert can take up to
a minute to issue on first request — a browser warning before then is expected.
Note: Let's Encrypt validates over the public domain, so a /etc/hosts entry alone
won't get you a trusted cert (use it only for plain-HTTP testing).
{{- end }}

Check the rollout:

  kubectl get pods -n {{ .Release.Namespace }}

WARNING: KEDA's HTTP add-on is not installed on this cluster.

Deployed apps are scaled by KEDA and routed through its interceptor, so they
will return 404 until it is present. `scripts/install.sh` in the marsa repo
installs it; to do it by hand:

  helm repo add kedacore https://kedacore.github.io/charts
  helm upgrade --install keda kedacore/keda \
    --namespace keda --create-namespace --version 2.20.2
  helm upgrade --install keda-add-ons-http kedacore/keda-add-ons-http \
    --namespace keda --version 0.15.0 \
    --set interceptor.replicas.min=2 --set interceptor.replicas.max=4
{{- end }}
